# 开发与双平台交付

## 工程骨架

| 路径 | 作用 |
|---|---|
| `src/main/` | Electron 启动、窗口、preload 和云端 API 客户端 |
| `src/renderer/` | React 连接页、结果浏览和样式 |
| `src/shared/` | 主进程、preload 和界面的 IPC 类型 |
| `scripts/write-cloud-config.mjs` | 校验构建时的唯一云端地址并生成打包配置 |
| `docs/` | 架构、接口和交付文档 |
| `dist/` | 构建产物，由脚本生成 |

`npm ci` 按锁文件安装依赖，`npm run typecheck` 检查主进程和渲染进程，`npm run build` 编译两个进程，`npm start` 打开已编译的窗口。`npm run dev` 合并构建与启动。当前使用本地 HTML 加载界面，便于开发时验证与打包后相同的加载方式。

本机合成联调的复跑步骤和各平台验证状态见 [联调与验收](verification.md)。

## 实施顺序

1. **连接与鉴权**：已实现预设 HTTPS 地址、令牌登录、`/v1/me` 检查及会话清理。正式账号登录与会话接口待云端提供。
2. **结果浏览**：已实现转写和分析产物的分页、按本地时区显示时间及关联转写展开。确定任务状态接口后再显示分段处理进度。
3. **MCP 配置**：复用上游 `stdio` 入口，给 Codex 和 Claude Code 提供配置示例与连接验收。以同一云端账号的授权为基准。
4. **发布准备**：选定打包工具，在 macOS 和 Windows 的构建环境中分别产出安装包，验证应用签名、首次启动和升级。MCP 若随 App 发行，按平台打包可执行文件，检查它在干净机器上无需预装 Python 即可启动。

## Apple Silicon 本机预览包

在 Apple Silicon Mac 上安装依赖后，运行：

```sh
npm run package:mac-preview -- /path/to/output
```

解压生成的 `EAR-Desktop-Preview-arm64.zip`，把 `EAR Desktop Preview.app` 拖到「应用程序」并打开。用由 43 个小写字母 `s` 组成的合成令牌登录。预览版随应用启动本机 HTTPS 服务，使用独立的应用名称、标识和数据目录。证书在运行时生成，仅在预览进程内受信任；测试服务只监听 `127.0.0.1:18877`。退出应用会停止服务。

该包用于本机预览，使用临时签名。对外发行需单独完成 Developer ID 签名、公证和安装升级验收。真实云端连接仍按 [接口与配置](integration.md) 构建。

## 首版验收

| 范围 | 完成标准 |
|---|---|
| macOS Apple Silicon、Windows x64 | 在各自系统从干净检出安装依赖、类型检查、构建并启动。发布前在干净系统验证安装包和 MCP 路径。 |
| 云端连接 | 有效令牌可识别当前账号，错误令牌和断网有独立提示，退出登录后清除上一账号的内容。 |
| 手机至桌面 | 合成录音上传后，云端识别、入库并生成配置的分析产物。两端可查到一致的转写及结果，并回看关联证据。若上线处理状态，再覆盖失败与重试。 |
| AI 客户端 | Codex 和 Claude Code 按需启动本机 MCP，并查询与桌面一致的已入库证据。 |
| 日志与权限 | 日志不含令牌或转写正文。私有试点验证两位用户分别只能看到自己的数据。 |

本仓库负责桌面代码与交付。手机上传协议、云端 API 和模型部署属于对应的上游仓库。接口变更优先由提供方更新契约，桌面端同步结果解析和验收样例。
