# 云端接口与 MCP

上游接口以 [EAR API](https://github.com/Echo-As-Record/Echo-As-Record/blob/dev/services/api/README.md) 和 [接收服务](https://github.com/Echo-As-Record/Echo-As-Record/blob/dev/services/ingest/README.md) 为准。本文记录桌面端怎样使用这些接口，以及还需要云端确认的契约。桌面端已实现 HTTPS 连接和只读结果浏览。macOS 已通过合成 HTTPS 服务联调，真实云端实例需另行验收。

## EAR API

| 能力 | 状态与使用方式 |
|---|---|
| 检查授权 | 已有 `GET /v1/me`。在预设的云端 API 核对普通用户令牌与账号。 |
| 读取逐句转写 | 已有 `GET /v1/records/transcript_segment`。按所选本地自然日的 UTC 边界查询，沿用服务端时间顺序和游标，每页请求 20 条。 |
| 读取活动和分析结果 | 通过 `GET /v1/records/artifact` 读取分析产物，将 `payload.body_md` 渲染为 Markdown。正文中的链接只显示文字，图片和原始 HTML 不加载。`payload.evidence_ids` 中能读取为 `transcript_segment` 的引用可展开为原始转写。 |
| 周历覆盖 | `GET /v1/week-coverage` 按所选周查询来源事件和活动的五分钟覆盖格。覆盖无法读取时，选日与结果浏览仍可用。 |
| 查看单条证据 | 已有 `GET /v1/records/{type}/{id}`，可选版本号。访问仍受云端权限约束。 |
| 查看每段录音的处理中、失败和完成状态 | 待约定云端可查询的任务状态接口，以及手机会话、上传分段、入库记录和分析产物之间的关联。仅凭查询不到转写，无法区分尚未生成、失败和没有权限。 |

部署方在构建时设置 `EAR_DESKTOP_API_URL`，写入发行版随附配置。必须是 HTTPS 根地址。缺省时应用显示未配置。运行时环境变量和渲染进程不能更改已构建的目标地址。首版使用普通用户 Bearer 令牌。分析笔记和录音转写共享周历，分视图分页。翻页会保留所选自然日的查询边界。周历蓝线来自来源事件，红线来自活动记录。支持首次加载、手动刷新和加载下一页。关闭窗口或断开连接会取消进行中的请求。已登录的读取请求收到 401 时清除会话和结果并返回登录。连接失败时可刷新重试当天结果和周覆盖。权限不足和空结果分别显示。自动刷新和处理进度待任务接口确认。

连接成功后清空令牌输入框，令牌只在主进程的窗口会话内使用。系统加密存储留待持久化连接设置时引入。渲染进程通过有限的 IPC 读取结果。访问令牌和转写正文不进入应用日志、示例配置或仓库。请求验证 HTTPS 证书并拒绝重定向。

## 云端账号与数据隔离

**已确定的目标**是让所有用户登录同一个云端入口，云端按可信用户身份隔离数据。一个入口可以对应不同的存储实现，具体方式由云端决定。当前 `/v1/me` 只核验已签发的令牌，正式账号登录、会话签发与续期、记录级隔离需在云端实现或确认。

云端从受认证的设备绑定或登录会话确定数据所属用户，并在接收、识别任务、入库、查询和证据回读中沿用。手机上传的 `X-User-Id` 当前仅是元数据。桌面和 MCP 均按云端登录身份查询。

面向真实用户前，用两个账号验证各自能正常读回自己的数据，同时无法跨账号访问。覆盖上传归属、列表分页、已知 ID 查询、关联原文和原音，以及后台任务写入。

## 上传与分析触发

手机直接调用云端接收服务的 `POST /api/v1/record`，按 EarRecorder 现有协议上传音频及配套 Context。手机上传地址和口令属于接收服务，桌面使用的是 EAR API 地址和用户令牌。

当前接收服务配置事件通知后可启动兼容识别交接。云端需要把转写入库、分析触发、结果持久化和状态接口接好，才能做到每个已上传分段自动分析并在桌面显示。现有分析模块和配置不代表这条自动链路已部署。推进时先确定幂等分段标识、任务状态与重试行为，再用一段带 Context 的合成录音跑通完整链路。

## 本地 MCP

使用上游现有的 `stdio` 入口。开发联调可在 EAR 源码仓库根目录使用：

```sh
uv run --frozen --package ear-api ear-mcp
```

这条命令由 AI 客户端配置启动。通过该进程的环境提供 `EAR_API_URL` 和 `EAR_API_TOKEN`。工作目录应指向上游 EAR 源码，或由启动命令明确选择上游项目。令牌由调用方安全注入，示例只写变量名称。安装版应明确处理 AI 客户端独立启动 MCP 时如何取得凭据，避免假设它能解密桌面 App 保存的凭据。

MCP 首版验收以实际查询 `find_evidence` 为准，验证其返回同一云端实例的已入库证据。个别工具的权限和作用由上游定义。凭据缺失或无权访问应显式报错，工具能被枚举不代表数据查询已连通。
